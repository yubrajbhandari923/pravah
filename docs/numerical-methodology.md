# Numerical verification and uncertainty methodology (Phase 3)

Scope: the definitions and rules used to judge numerical error and statistical uncertainty in the Phase 3 experiments (EXP-015 to EXP-019), the results that exist
for the scheme and field convergence checks, and which kind of evidence each result is. Everything is synthetic: real Belauri geography with synthetic emissions,
winds and noise, or a toy domain. Numbers are quoted from the files named; findings F-0xx are `preliminary` unless the Research OS says otherwise
(`.research/bin/research current`).

## 1. Four kinds of evidence (do not mix them)

| Kind | Question | Phase 3 results that belong here | Not shown by it |
|---|---|---|---|
| Mathematical verification | Does the code solve the stated equations correctly (exact/manufactured solutions, conservation, positivity, order)? | `results/phase3-scheme/` (periodic Gaussian vs exact solution, Courant sweep, budget residuals); the Phase 1/2 verification record (`validation.md`, `verification.py`); unit tests (linearity of responses, closure, face-divergence < 1e-12 for the wind builders) | that the equations describe the atmosphere |
| Numerical convergence | Do the numbers (fields, then decisions) stop changing as mesh, dt and scheme are refined? | EXP-015 stage 1 (RUN-0028, F-022: fields); EXP-015 stage 2 (decisions: **not run yet**) | that the converged answer is right: the reference is itself a discretisation |
| Synthetic robustness | How do estimates and sensor decisions behave when the truth differs from the assumed model (wind error, omitted source, different mesh), with the truth generated by the same family of code? | Phase 2 EXP-013/014 (F-020, F-021); EXP-017 toy population design (F-023); EXP-018 prescribed winds (F-024); EXP-019 toy wind error (pending) | any real-world error size: the "truth" shares numerics, structure and noise model with the estimator (inverse-crime risk) |
| Empirical validation | Does the model agree with measurements? | **None.** No measured concentration, emission, wind or population distribution is used anywhere. Real geography only supplies the study polygon, roads, buildings and relief. | - |

Every figure, README and table carries a label ("Real geography; synthetic emissions and meteorology", or "EXP-018 prescribed wind, not terrain-derived"). Keep it.

## 2. Definitions

* **Relative space-time L2 error on a common grid** (`scripts/convergence_stage1.py`, `rel_l2`): fields from every mesh are block-averaged to the common 500 m grid (66 x 65), output times
  `t >= t_exclude = 7200 s`, and `rel_L2 = sqrt( sum (a - r)^2 / sum r^2 )` over all retained times and cells, where `r` is the reference field. Block averaging makes meshes comparable (cell-average
  of the fine field) and removes the partial-cell geometry of the study polygon from the comparison; the study-mean concentration series (weights = 500 m `study_fraction`) is reported separately
  (`mean_err_max`, `mean_err_rms`).
* **K_eff / K.** The discretisation (FiPy exponential convection + diffusion, backward Euler) adds diffusion to the nominal K. For a Fourier mode, wind along a grid axis, cell Peclet number
  Pe = |u| dx / K: `K_eff/K - 1 = (Pe/2) coth(Pe/2) - 1 + u^2 dt/(2K)` (`geo.scenarios.numerical_diffusion_estimate`; `specification.md`; reproduced to 3 % by `verification.py`). For oblique wind and for
  vanleer this is not a measurement. In the periodic Gaussian test (`scheme_check.py`), K_eff/K is measured as `1 + (var_num - var_exact)/(2 K T)` with `var` the isotropic second moment about the centroid,
  so the exact field's own periodic-truncation bias cancels. It is not a verification of K itself. Report K_eff/K separately from the physical K: at 500 m it is 6.3 (F-022; the older range 2.4-9.4
  for the Phase 2 winds in F-016/F-018).
* **Observed order.** `p = log2(e_coarse / e_fine)` for successive halvings of dx (or dt), from errors against a stated reference (`convergence_stage1.py`, `order_status`; reported non-monotone otherwise, never
  forced). A Richardson estimate `p = log2((u0 - u1)/(u1 - u2))` on the time-mean of the study-mean is computed from three levels and flagged "not converging" when successive changes grow.
* **Reference and reference floor.** There is no exact solution for the Belauri case, so the reference is the finest available discretisation (125 m, dt 25 s, exponential; and the same with vanleer). Two
  125 m references (exponential and vanleer) differ by about 0.8 %: errors below about 1 % cannot be resolved against them. This is the **reference floor**; quote errors relative to it, and never call a
  mesh-error of that size "converged to truth".
* **Time-step self-error.** dt errors at 500 m are measured against the 500 m dt 12.5 s run (the 12.5 s level has no error by construction).
* **Mass closure.** Relative mass-budget residual of the forward diagnostics (emitted - removed - boundary loss - remaining) / emitted; stop rule 1e-8 (EXP-018). Observed 6e-14 to 1.2e-10.
* **Positivity.** Minimum concentration and number of negative cells; all schemes tested are nonnegative on the tests below.

## 3. Results that exist

### 3.1 Scheme check, `results/phase3-scheme/scheme_check.csv` (`scripts/scheme_check.py`, about 90 s)
Periodic 2-D Gaussian against the exact translating/spreading/decaying solution, nx = 20/40/80, dt tied to dx (dt = 0.06 dx):

| scheme | rel L2 (nx 20 / 40 / 80) | observed order (20->40, 40->80) | K_eff/K (20 / 40 / 80) |
|---|---|---|---|
| exponential | 0.161 / 0.061 / 0.019 | 1.41, 1.65 | 1.93 / 1.30 / 1.09 |
| upwind | 0.239 / 0.140 / 0.077 | 0.77, 0.87 | 2.69 / 1.85 / 1.43 |
| vanleer | 0.040 / 0.0079 / 0.0023 | 2.34, 1.80 | 1.035 / 1.000 / 1.000 |

Fixed dt = 7.5 s gives nearly identical numbers. Courant sweep (dx 250 m, u 1 m/s, Courant 0.25 to 4): exponential rel L2 rises from 0.126 to 0.475 and K_eff/K from 1.38 to 2.76 (the time term of
the estimate grows with dt); upwind 0.211 to 0.500; vanleer stays 0.0055-0.0064 (its sub-stepping caps the effective Courant). Open-boundary steady case (nx 25 vs a cell-averaged exponential nx 100
reference, which carries its own numerical diffusion, so this is a consistency check): exponential 0.0447, upwind 0.0646, vanleer 0.0163. Minimum value 0 in every case (no negative values), budget residual
about 1e-15. Statement in the F-016 spirit: the baseline scheme is mass-consistent, first order in time, observed spatial order about 1.4 in the periodic test, and strongly diffusive.

### 3.2 Field convergence on Belauri, `results/phase3-convergence/` (stage 1, RUN-0028, F-022 preliminary)
One production-like case (`configs/geodesign.json`, draw d0 of the design ensemble), one wind segment, fields block-averaged to 500 m; 23 solves in 43 min. At dt 25 s the 500 m exponential field has
5.0 % relative space-time L2 error against the 125 m solution (250 m: 1.5 %), observed order about 1.4-1.7; at 500 m the time-step self-error (dt 100 vs 12.5 s) is 0.6 %, so mesh error dominates; K_eff/K is
6.3 / 3.5 / 2.3 at 500 / 250 / 125 m; the external-patch fingerprint (that source group alone) is the worst resolved (L2 9.8 % at 500 m, 2.9 % at 250 m). Vanleer at 500 m is about as accurate as exponential at
250 m. No negative cells; mass residual <= 1.2e-10. **Limits (in F-022):** one draw; references discretised (floor 0.8 %); vanleer orders and the Richardson estimate are not asymptotic and are not interpreted;
arrival time is local-source driven and says nothing about the external plume; the in-study fraction of each source varies with mesh (road 0.949-0.986, builtup 0.977-0.995), so the local/external label shifts a few percent with mesh.
It supports "500 m dt 100 is mesh-limited, not time-limited" and nothing yet about layouts.

## 4. The vanleer scheme

`SolverOptions.convection = "vanleer"` uses FiPy's `VanLeerConvectionTerm` (commit 706d1d2): a flux-limited, second-order-capable scheme. Consequences that matter for method:

* **Sub-stepping.** The convection is explicit, so `simulate` sub-steps the whole equation so that the summed axis Courant number is at most `VANLEER_MAX_COURANT = 0.5`. For Courant > 0.5 the effective dt is
  smaller than the nominal dt, so scheme and time step are confounded: always report `dt_eff = dt / max_substeps` (stage 1 does, column `dt_eff_s`).
* **Nonlinearity.** The limiter makes the map from emission amplitudes to concentrations nonlinear. The cached-response (superposition) route, on which all design work is built, assumes linearity; the cache and
  `inverse.compute_responses` refuse vanleer (`ValueError`). A vanleer arm in a sensor-design study would need direct solves per candidate layout. So vanleer is used only for field verification and, possibly, as a less
  diffusive truth generator via direct solves (an inverse-crime check; not implemented).
* **Orders.** Its observed orders in the Belauri stage 1 are not asymptotic; do not quote them.

## 5. Decision-stability metrics (EXP-015 stage 2; code in `scripts/convergence_stage2.py`, not yet run)

Question: do the sensor layouts chosen by `greedy_total` change when only mesh and dt change, relative to how much they change when the design scenarios are resampled? Layouts of budget b (3, 5, 8) are compared
with the reference layout (250 m, dt 50), sites located in UTM metres (the candidate table is built once; each mesh looks the site up by cell, never reusing cell indices).

* **Jaccard** of the two site sets: |A ∩ B| / |A ∪ B| (exact overlap; near-ties make it pessimistic).
* **Assignment displacement.** Optimal one-to-one assignment (Hungarian, `linear_sum_assignment`) of the sites of one layout to the other by UTM distance; report the mean and maximum displacement in metres and the
  fraction of assigned pairs within each tolerance tau (500 m, 1000 m).
* **Regret.** `J_ref(layout_c) - J_ref(layout_ref)`: the reference-mesh design objective of the layout chosen on config c minus that of the reference layout, on the reference design cases (units (ug/m3)^2). Nonnegative
  up to greedy sub-optimality; small regret with large displacement means near-ties.
* **Test RMSE** of each layout evaluated on reference-mesh truths of the 6 test cases (303; 304 held for a final fresh test), as a difference to the reference layout.
* **Replicate (resampling) baseline.** R = 8 replicate design ensembles of 6 cases each (new case seeds 1101-1108, disjoint noise seeds) on the 500 m, dt 100 mesh. All replicate-pair displacement, Jaccard and
  |regret| values give the distribution against which mesh-induced values are judged ("layouts moved by sampling, not numerics" is H1). Limitation (the optional HPC extension): this baseline lives on the 500 m mesh,
  not the reference mesh.
* **Epsilon-optimal set / ties.** For the reference layout, all single-site swaps (to any interior candidate) are scored on the reference design cases; the epsilon set is the swaps whose objective is within one
  replicate SD of the reference layout's objective (SD over the replicates of the reference layout's objective on each replicate ensemble). `eps_set_size`, `n_swaps` and `tie_fraction` quantify how flat the objective is.
* **Stability claim (pre-registered).** Stable only if mesh-induced displacement and |regret| lie within the replicate-pair interquartile range AND decrease monotonically from 500 to 250 m at dt 100. There is no
  universal threshold; tau fractions and tie fractions are reported alongside. Alpha (0.01), noise sigma (fraction x the frozen validation signal scale), budgets, tau and the reference are frozen before the test ensemble is built and must not
  change afterwards.

Stage-1 evidence shows that fields differ by about 5 % between 500 m and 125 m; whether that moves the layouts is exactly what stage 2 measures. Earlier evidence (F-021, EXP-014: Jaccard 0-0.2 between 500 m and 250 m
selections) had no resampling baseline and unequal case counts, so it is not a stability result.

## 6. Uncertainty wording rules

* A **standard deviation (sd)** is a spread over cases or replicates, never a confidence interval. Report it under that name.
* With 6 to 32 test cases, the interval reported for a paired difference is a **percentile bootstrap interval over test cases** (resampling cases with replacement; `population_design.bootstrap_ci`,
  `windunc.paired_bootstrap`; 2000-10000 resamples; 95 %). Write it in full: "percentile bootstrap interval over test cases (resampling cases; not a confidence interval for new scenarios)". It describes the
  sampling variability of the mean over THESE case draws; it does not cover truth-model error, mesh error, or scenarios outside the ensemble. Always state n.
* The unit of replication is the **case** (scenario draw), not the row (layout x case x noise rep): rows share a case and are not independent. Rows are used only for diagnostics.
* An effect is **called resolved** only if the interval excludes 0 AND (where pre-registered) the same sign holds in a stated fraction of cases (EXP-016/017: >= 75 %). Otherwise say "not resolved at n cases", not "no effect".
* Rankings and "winner" counts are reported with the noise baseline: a contrast kept in sign 50 % of the time is chance (F-021 lesson); count exact-zero contrasts separately.
* Predictive intervals from an estimator (EXP-019 strategy C: Gaussian with weighted member spread + posterior variance) are reported with their empirical 90 % coverage and chi2/dof, never as guarantees; the interval is only
  as good as the declared wind prior. The chi-square-per-dof model check uses a noise sigma that is known and fixed from the validation scale, not from the test ensemble (G2 fix).
* Numbers are taken from files, not memory; preliminary findings are labelled so until an independent review. Diagnostics that are saturated by construction (identifiability flags in the geodesign runs, F-021) are not evidence of anything.
* Discretisation error is NOT part of any interval above; it is reported separately (sections 3 and 5).

## 7. Freeze and independence rules (statistical hygiene)

Design, validation and test ensembles use disjoint scenario seeds and noise-seed ranges (guards in the code, listed in `hpc-runbook.md` section 0); alpha is chosen on validation only (area objective only, alpha-independent
random and spread layouts) and frozen; the noise sigma is a fixed number from the validation scale for all ensembles (an earlier version used the test ensemble's own scale, 2.6 % off: the G2 fix); a configuration hash is
written before test cases are built and re-checked after (`freeze.json` / `provenance.json`); test cases are used only for evaluation. A pilot or smoke profile is labelled EXPLORATORY, has its own seeds, and its numbers are
never combined with a production result.
